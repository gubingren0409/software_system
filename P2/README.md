硬件事件均可实际采集，分支误预测率为 `114172 / 752986666 × 100% = 0.01516%`。计数与采样分别运行相同输入配置，计数值不等于另一轮采样的估计事件总数。

主要命令如下；`$P2` 为本作业目录，`$PERF` 为上表中的完整 Perf 路径。

```bash
taskset -c 0 "$PERF" stat -x , \
  -e cycles:u,instructions:u,branches:u,branch-misses:u \
  -- "$P2/results/stage-a/binaries/isort-debug.elf" 10000 10

# 采样先写 Linux 文件系统，完成后复制进 results/stage-a/checkoff1/
taskset -c 0 "$PERF" record -e cycles:u -F 999 \
  -o /tmp/p2-isort-perf.data \
  -- "$P2/results/stage-a/binaries/isort-debug.elf" 10000 10
"$PERF" report -i /tmp/p2-isort-perf.data --stdio --no-children --sort=symbol
"$PERF" annotate -i /tmp/p2-isort-perf.data --stdio -l -s isort
```

正式采样得到 **788 个样本，丢失 0 个**。对 `perf script` 导出的样本按 `period` 加权，分母取 `isort` 全部样本权重，包含未解析行号的样本；[isort.c 第 20 行](recitation/isort.c#L20)的权重占比为 **95.35%**：

```c
while (index >= left && *index > val) {
```

`perf annotate` 顶部源码行摘要显示 94.45%，是因为本次 [Perf 6.8.12 的 `annotation__calc_lines`](https://github.com/gregkh/linux/blob/v6.8.12/tools/perf/util/annotate.c) 先丢弃单条指令贡献不超过 0.5% 的项，再按源码行合并。使用已有逐样本输出离线核对：第 20 行完整 period 为 `1,299,100,602`，`isort` 全部 period 为 `1,362,398,487`，比值为 `95.35393751505245%`；过滤后为 `1,286,723,959 / 1,362,398,487 = 94.4454923634982%`。少计 `12,376,643`，即 `0.908445151554253` 个百分点。两者口径不同，95.35% 保留完整样本权重；[逐指令核对](results/stage-b/audit/annotate-filter/stdout.txt)没有重新采样或修改历史数值。

最高权重的单条指令归于同一行，ELF 地址为 `0x11f0`，即 `isort+0x60`，占 `isort` 样本权重的 **67.65%**。对应的条件判断及邻近指令为 AT&T 语法：

```asm
11de: mov  -0x28(%rbp),%rax
11e2: mov  (%rax),%eax
11e4: cmp  -0x1c(%rbp),%eax
11e7: seta %al
11ea: mov  %al,-0x29(%rbp)
11ed: mov  -0x29(%rbp),%al
11f0: test $0x1,%al
11f2: jne  11fd <isort+0x6d>
```

随机输入下，每插入一个元素都可能反复比较并后移前面的元素，总工作量为二次量级。`-O0` 还保留了循环变量、布尔中间值在栈上的多次读写，因此这段循环执行了大量指令。观测到的分支误预测率很低，不能据此把主要瓶颈归为分支预测失败。`test` 的高占比表示周期采样的归属，不能说明这条指令本身有这么大的执行延迟；非精确采样存在偏移，还需结合邻近的加载、比较、分支和整个循环理解，不能当作精确逐行计时。

固定 `N=1000000` 改变 U 时，仅比较整进程缺失率会受初始化工作量影响。因此另看源码注释归于 [sum.c 第 38 行](recitation/sum.c#L38) `val = (val + data[l]);` 的读取，该行在四种配置下均有 1,000,000 次读取：

| 数组工作集 | 第 38 行 D1 读缺失率 | 第 38 行 LL 读缺失率 |
|---|---:|---:|
| 16 KiB | 0.0008% | 0% |
| 1 MiB | 96.9260% | 0% |
| 40,000,000 B，约 38.15 MiB | 99.9178% | 0.0024% |
| 128 MiB | 99.9746% | 50.3044% |

16 KiB 工作集能留在 D1 中；1 MiB 与约 38.15 MiB 的工作集超过 D1，但可留在模拟 LL 中。128 MiB 超过 64 MiB 的 LL，随机读取的 LL 缺失率约为一半，符合这个直接映射模型下的预期。这里的单行统计按编译器的源码归属读取，整进程其他缺失仍单独保留。

固定 `U=10000000`，将 N 从一亿降到一百万，D1 缺失总数由 100,546,117 降至 1,626,020，主要是工作量减少。第 38 行的 D1 读缺失率在三个 N 下仍分别为 `99.9178% / 99.91843% / 99.919275%`，没有改善访问局部性；LLd 缺失总数也仍在 626,000 左右，主要来自相同规模的初始化。整进程缺失率会随初始化与随机访问的占比变化，不能直接将其下降解释成局部性改善。

要减少缓存缺失，可在任务允许时缩小工作集，使其进入较近的缓存，或重排访问来增加同一缓存行、同一小块数据的连续复用。单纯减少 N 只能减少访问次数。本次对照只改变编译期 U/N 常量，保留原题随机访问和累加语义，没有把访问顺序优化混入默认配置。

`sort_a.c` 的一行汇总合并了该文件内的递归、归并和复制代码归属；它不包括 `malloc/free`、`util.c` 或参考排序的执行成本，不能作为整个排序调用的包含式指令数。该项与整进程总数分开列出，用于观察基线算法代码本身的变化。

正常耗时另行采集。Debug、Release 交替运行，各做 5 次独立进程实验，并固定到逻辑 CPU 0；每个进程分别取每类输入 5 次排序的平均值，下表再报告这 5 个进程平均值的中位数和最小—最大范围。计时边界为 `CLOCK_MONOTONIC` 紧邻 `sort_a(data, 0, N-1)` 的前后，包含其内部归并、内存分配与释放，不包含数据生成或结果校验。

|---|---:|---:|---:|

## Stage A 结果小结

插入排序的热点位于第 20 行的内层循环条件及其后移操作；高样本占比需要结合循环工作量和采样偏移解释。`sum` 的随机访问在工作集超出 D1 后几乎每次都发生 D1 缺失，超出模拟 LL 后又出现明显的 LL 读缺失。归并排序基线的 Release 构建减少了动态指令并改善原生时间，但缓存缺失绝对数并未按相同比例下降，指令数只能作为性能比较的一项依据。

## Stage B 比较方法与正确性

六个版本保留相同公共签名 `void sort_x(data_t*, int p, int r)`，辅助函数保持 `static`。`sort_a.c`、`util.c`、`util.h` 不变；i/p 将分配和释放的小包装复制为局部等价函数，使内联不会改变基线调用路径。正式比较统一使用 `DEBUG=0`、`-O3 -DNDEBUG -g -Wall -std=gnu99 -gdwarf-3`，另加只输出内联诊断的 `-Rpass=inline -Rpass-missed=inline`。六个算法来自同一个 [Release ELF](results/stage-b/final/binaries/release.elf)，没有降低 a 的优化等级或禁止其自动内联。[最终配置](results/stage-b/final/configuration.json)与[源码/二进制清单](results/stage-b/final/build-manifest.json)固定测量对象。

新接口如下，默认仍选 a；未知版本、非法数值、未知选项均返回非零。`-b` 只选计时测试组，去掉它会执行完整正确性测试。每次输出都有算法、输入、N、R、种子、逐次时间和实际顶层调用数；`--variant all -b` 每个版本各调用 `2R` 次，不会把所有版本混入一个单版本结果。

```bash
cd P2/homework
make --always-make DEBUG=0
taskset -c 0 ./sort --variant f -b -s 20261026 1048576 5
./sort --variant all -s 42 33 1
```

原题 `rand_r` 输入范围为 `0..2147483647`。a/i/p/c 使用 `UINT_MAX` 哨兵，本次不扩展为可含 `UINT_MAX` 的任意无符号输入。命令行限制 `1 <= N <= INT_MAX/2`，使保留基线的 `(p+r)/2` 不发生有符号溢出；空区间在内部测试中覆盖。m/f 不依赖哨兵，但统一按同一输入域比较。

Release、Debug 的六个版本均通过 `qsort` 参考结果逐元素核对。每个版本各有 230 个模式/子数组测试：空、单元素、2/3 元素、奇数、非二次幂、阈值附近，以及正序、逆序、随机、重复值、全相等，起点为 0 或 2，并检查区间外元素不变。尺寸列表保留了与固定 K 邻域重合的项，所以 230 是实际执行的用例数。N=33、R=1 的完整测试每个版本实际调用 234 次。Memcheck 对同一套小规模测试报告 **0 错误、0 未释放块**，66,033 次分配与释放相等；8 条非法命令退出 1，故意输出全零的故障版本也因元素不匹配退出 1。[校验汇总](results/stage-b/correctness/verification.json)及[Memcheck 原文](results/stage-b/correctness/memcheck/stderr.txt)保留这些证据。

单版本与 all 模式均先生成输入，再把相同原数组恢复给各算法；逐次输入指纹一致，换种子后随机输入指纹改变。正式矩阵使用种子 `20261026`、CPU 0、N=131072/1048576，六版本每规模各 5 个独立进程，每进程 random 和 inverted 各排 5 次，共 60 个进程、600 条排序时间。按[轮换顺序](results/stage-b/final/native-order.json)运行，原生、Perf、Cachegrind 作业顺序执行。计时仅包围顶层排序调用，包含其分配/释放，输入生成、复制、指纹、参考排序和输出均在计时外。先从五次逐次时间计算进程均值，再对五个进程均值取中位数及最小—最大范围。相对 a 的加速比定义为本轮 `T_a/T_x`，直接比较采用 `T_比较版本/T_当前版本`；Stage A 旧时间不参与这些比值。

## Write-up 6

**作答**

[sort_m.c](homework/sort_m.c) 从 c 派生，每次归并只复制左半段到临时数组，右半段从原数组读取。设左侧已读 i 个元素，右侧游标 j，输出游标 k，左长为 n1，则始终有 `j-k = n1-i`。只要左侧未耗尽，`j>k`，写 `A[k]` 不会覆盖尚未读取的 `A[j]`；右侧耗尽后复制左侧余项；左侧先耗尽时 `j=k`，原地右侧余项已在正确位置。这也适用于奇数长度和非零起点。

长度 n 的旧归并同时申请 `n+2` 个元素（含两个哨兵），新归并只申请 `ceil(n/2)` 个元素，`data_t` 为 4 B，所以根归并从 `4(n+2)` B 降为 `4ceil(n/2)` B，约减半。子调用归并结束后才开始父归并，各层临时空间不会叠加；此处讨论临时堆空间，递归栈仍为 O(log n)。m 保留每次归并的申请/释放，并未提前改成一次分配。

独立分配诊断使用 N=131073、起点3，包住一次顶层调用，仅统计排序期间的请求字节，不含分配器元数据。结果如下，所有版本最终活动字节均为 0，输出及区间外元素均匹配参考结果；诊断构建未进入正式计时表。

| 版本 | malloc 次数 | free 次数 | 累计请求，B | 峰值活动，B |
|---|---:|---:|---:|---:|
| a | 262,144 | 262,144 | 9,961,548 | 524,300 |
| i | 262,144 | 262,144 | 9,961,548 | 524,300 |
| p | 262,144 | 262,144 | 9,961,548 | 524,300 |
| c | 16,384 | 16,384 | 6,881,400 | 524,300 |
| m | 8,192 | 8,192 | 3,407,960 | 262,148 |
| f | 1 | 1 | 262,148 | 262,148 |

m/c 在逆序输入上加速 `1.470 / 1.494`，随机输入时间则增加约 `15.6% / 20.0%`。代表模拟中，D1 缺失从 c 的 `4,458,729` 降至 m 的 `3,907,608`，但排序文件 Ir 从 `325,761,163` 升至 `357,386,432`，条件分支从 `131,720,177` 升至 `146,269,059`。减少复制与分配并没有抵消随机归并的边界检查、控制和数据依赖开销。逆序的比较结果和左右耗尽方式更规律，收益较大；这是与数据一致的解释，整进程模拟不能单独证明每种微观原因。

编译器能优化复制循环或内联辅助函数，但通常不能从原来的两份哨兵缓冲自动推导出这种算法变换：它需要同时改变哨兵终止条件、存储布局、读写顺序和分配/释放语义，并证明原数组右半段与输出重叠时不破坏未读数据。单缓冲循环中还存在上述读写依赖，普通别名和循环分析不会自然得到整个归并不变量。因此需要显式实现并验证，不能期待加大优化等级自动完成。

## Write-up 7

[sort_f.c](homework/sort_f.c) 从 m 派生，在顶层调用内申请 `ceil(n/2)` 个元素，通过私有递归函数传入。左右子调用顺序执行，完成后父节点才覆盖 scratch 的开头，任何子问题左半长度都不超过根容量，因此可以复用同一块空间。空、单元素和不超过 K 的区间不分配；正常大区间结束后释放，申请失败直接非零退出。没有跨顶层调用缓存，申请与释放都位于被计时的 `sort_f` 内。
