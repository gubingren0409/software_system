## 4. 老师源码分析

重要位置均指向保存的原件
[`code/original/matrix_multiplication.c`](../code/original/matrix_multiplication.c)。

### 4.1 语言、编译、运行和依赖

**已验证事实：** 这是 C99+ 源码；第 1-4 行包含 libc 头和 POSIX
`sys/time.h`。在 WSL 中可用以下模式编译：

```bash
gcc -std=c11 -Wall -Wextra -Wpedantic -O3 \
  code/original/matrix_multiplication.c -o matrix_multiplication
./matrix_multiplication 24
```

第 19-20 行要求恰好一个块大小参数并用 `atoi` 解析。除 libc/POSIX 接口外无其他
文件依赖。P0 已实际验证 O0/O1/O2/O3 均可无警告编译并保留四份原始日志。

### 4.2 矩阵、布局与初始化

**事实：** 第 6 行固定 `n=4096`；第 8-10 行声明三个文件作用域
`double[4096][4096]`，C 语言行主序连续布局。每个矩阵 128 MiB，合计 384 MiB。
第 26-32 行遍历全部元素，A/B 使用未显式 `srand` 的 `rand()/RAND_MAX`，C 清零。
同一 libc 中默认随机序列通常可复现，但 C 标准不保证跨 libc 相同。

### 4.3 循环顺序、分块与边界

**事实：** 第 37-39 行块循环为 `ih -> jh -> kh`，第 40-42 行块内循环为
`il -> kl -> jl`，第 43 行执行 `C[i][j] += A[i][k] * B[k][j]`。三个块内
循环都有 `base + offset < n` 条件，因此不整除时仍覆盖尾块。

### 4.4 参数控制

**事实：** 分块大小 `s` 是第 20 行的运行时命令行参数，合法范围在第 21-24 行
限制为 1..4096；优化级别由编译命令的 `-O0` 到 `-O3` 注入。矩阵尺寸才是宏。

### 4.5 计时边界和单位

**事实：** 第 12-16 行计算 timeval 差并返回秒；第 35 行在初始化后开始，第 45 行
在完整乘法后结束，因此计时只含分块循环和计算，不含初始化、解析或输出。第 46 行
以六位小数输出。

**风险：** `tdiff` 返回 `float`，把 double 计算结果压缩到约 7 位有效数字；
`gettimeofday` 是墙钟而非单调时钟，可能受系统校时影响。正式基线应改为单调时钟、
`double` 秒值并提高输出精度。

### 4.6 结果使用与优化消除

**事实：** 第 43 行写 C，之后程序从不读取 C，只打印时间。

**风险：** 缺少校验或 checksum，输出不能证明计算正确，也不能形成稳健的跨工具链
结果保活保证。**本机限定的验证事实：** GCC 13.3 O3 反汇编仍包含 `mulsd`、
`addsd` 与 C 写回，当前工具链没有删掉核心循环；这不能外推到其他编译器/LTO。

### 4.7 正确性与安全风险

- 正常路径上 A/B/C 都先完整初始化，无未初始化读取。
- 尾界条件阻止越界；数组在全局 BSS，不占线程栈；4095 最大索引不会使 `int`
  溢出；[0,1] 的 4096 项 double 点积不接近数值溢出。
- `assert(argc==2)` 不是可靠输入校验：使用 `-DNDEBUG` 且缺参数时访问
  `argv[1]` 会产生未定义行为。
- `atoi` 不检查尾随字符；超出 `int` 可表示范围的转换行为不可靠。错误返回 `-1`
  在 Unix shell 中呈现为 255。
- 384 MiB 是静态虚拟存储，但初始化会实际触页；内存受限时进程可能被终止。

### 4.8 非整除与超大块

对任意合法 s，外层基址取 `0,s,...<n`，内层偏移取
`0..min(s,n-base)-1`，因此每个 i/j/k 均恰好覆盖。老师要求的 24 不整除 4096，
其尾块大小为 16，现有循环逻辑可以处理。

源码接口在第 21 行明确拒绝 `s>n`，所以“块大于矩阵尺寸”不受当前接口支持；
P0 诊断据此将 s=128、n=65 记为预期拒绝，而不是假称计算通过。

### 4.9 独立参考与浮点验证

P0 诊断副本保持老师的分块循环结构，另用朴素 `i-j-k` 和 `long double` 累加生成
参考值。每个元素采用预先固定的
`abs_error <= 1e-12 + 1e-12 * abs(reference)`，同时记录最大绝对/相对误差、失败
元素数和 checksum。正式实现仍需对全部 5 个块值、全部 4 个优化级别执行同样的
正确性门禁，不能只检查退出码或单一 checksum。

### 4.10 接入 Autotuner 的最小改动

P1 只应在工作副本上做以下必要修改：

1. 保留块大小 CLI 与编译器优化参数注入方式。
2. 让矩阵尺寸可在诊断构建中覆盖，正式默认仍为 4096。
3. 用严格 `strtol` 校验 argc、完整字符串和范围。
4. 固定并输出输入种子；在计时后消费 C 并输出高精度 checksum/验证信息。
5. 改用单调时钟与 `double` 时间；加入独立 correctness 模式。

## 5. 默认规模成本估算

- 元素数：`4096^2 = 16,777,216`。
- 三个 double 矩阵：`3 × 4096^2 × 8 = 402,653,184 bytes = 384 MiB`。
- A/B 初始化调用 rand 共 33,554,432 次。
- 乘法与加法各 `4096^3 = 68,719,476,736` 次，合计约
  137,438,953,472 FLOP（不含循环与寻址）。

因此 P0 先使用 n=65 完成有限诊断，并未启动默认规模 O0 长测或完整 20 组合。
